# FaselHDBot — آلية العمل

## 1) البنية (5 Runners في job واحدة)
```
┌──────────────┐  Quick Tunnel   ┌─────────────────────────┐
│  Runner 01   │◄───────────────►│  Runners 02–05 (عمال)   │
│ Main Bot     │   API :8000     │  claim → تحميل → رفع    │
│ + Redis      │                 │  → تقرير → تنظيف        │
│ + API server │                 │  (بوت + سيرفر لكل عامل) │
└──────┬───────┘                 └─────────────────────────┘
       │ long polling                  │ sendVideo للقناة
       ▼                               ▼
   @Videoplayeronlinebot          القناة (البوتات الخمسة أدمِن)
```
- الاكتشاف: الرئيسي ينشر رابط الـ Tunnel في artifact باسم `api-url` (ويعدّل به الرسالة 13 للعرض) — العمال يسحبونه عبر `gh` ثم يتصلون.
- مثيل واحد إجبارياً (`concurrency.singleton`) — دورتان متوازيتان تكسرا النظام (تحديثات متسابقة).

## 2) دورة حياة المهمة
1. مستخدم يرسل رابطاً → مؤشر typing → استخراج (اسم/Poster/Thumbnail/رابط Master) → **رسالة صورة واحدة** بالأزرار (⚡ بجانب الجودة المخزنة).
2. نقرة جودة: (مخزنة؟ → forward فوري + تعديل "sent instantly") وإلا → مهمة `queued` + تعديل "01 تحليل".
3. عامل يلتقط (`/claim`) → يستخرج Master طازجاً → يحمّل N_m3u8DL-RE بالجودة المطلوبة (تقارير `/progress` → تعديل "02 Downloading [bar]").
4. بعد التحميل: مرحلة "03 تحويل" (تقسيم ffmpeg عند >1.9GB) → رفع `sendVideo` مع thumbnail (تقارير → "04 Uploading [bar]").
5. `/done` (message_ids + الأحجام + thumb) → الرئيسي: يحفظ الكاش + يعيد توجيه الفيديو للمستخدم + يعدّل الرسالة لملخص نهائي (صورة Thumbnail + الاسم + Part + Quality + Size).

## 3) Redis (ذاكرة المنسق)
| المفتاح | المحتوى |
|---|---|
| `lang:<uid>` | ar/en |
| `done:<pageid>:<quality>` | JSON ‏{msgs, sizes, name, thumb, parts} — أساس الـ ⚡ |
| `task:<id>` | JSON المهمة (الحالة/العامل/التقدم/النتيجة) |
| `queue` (list) | الطابور (RPOP للالتقاط) |
| `active` (set) + `claimed_ids` (set) | المتداول + إعادة العالق للطابور عند بدء دورة |
| `hb:w1..w4` | نبض العمال (كل 60s) |
| `events` (list, آخر 50) | سجل حي يظهر في `/diag` |

## 4) API الرئيسي (منفذ 8000 عبر Tunnel)
| المسار | الاتجاه | الوظيفة |
|---|---|---|
| GET /health, /status, /diag | مراقبة | نبض/إيقاف/تشخيص (طابور+نشط+نبض+أحداث) |
| POST /claim {worker} | عامل→رئيسي | أقدم مهمة queued ← claimed |
| POST /progress {task,phase,pct,eta,speed} | عامل→رئيسي | تعديل رسالة المستخدم فوراً |
| POST /heartbeat {worker} | عامل→رئيسي | نبض |
| POST /fail {task,error} | عامل→رئيسي | إعادة للطابور + إبلاغ المستخدم |
| POST /done {task,msgs,sizes,parts,quality,thumb} | عامل→رئيسي | الإنهاء والكاش والإرسال |

## 5) حدود تليجرام المحترمة
- الرفع عبر السيرفر المحلي حتى 2000MB/ملف (الرسمي 50MB) — [الوثائق](https://core.telegram.org/bots/api#using-a-local-bot-api-server).
- التقسيم عند 1.9GB (هامش أمان) إلى PARTs صالحة.
- عند 429: نوم `retry_after` + إعادة (5 مرات) + فاصل 5s بين الأجزاء.
- `editMessageMedia` للـ media فقط — لذا الصورة تُرسل أولاً ثم تُعدَّل (لا تحويل نص→صورة).

## 6) الدورة 5 ساعات
بدء: استعادة `dump.rdb` (artifact الدورة السابقة، واحتياطياً رسالة 12) + إعادة العالق للطابور → تشغيل → قبل النهاية: BGSAVE + تعديل ميديا رسالة 12 + تعديل نص رسالة 13 + artifact + تشغيل دورة جديدة ذاتياً (تُمنع عند الإلغاء اليدوي).
