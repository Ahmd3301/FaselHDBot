# FaselHDBot — الفكرة

## ما هو؟
بوت تليجرام يعمل **24/7 فوق GitHub Actions** (بدون أي سيرفر خاص): المستخدم يرسل رابط حلقة/فيلم من fasel-hd، فيرد البوت بصورة الـ Poster واسم العمل وأزرار الجودات (1080p / 720p / 360p)، وبعد اختيار الجودة يتابع المستخدم مراحل حية (تحليل ← تنزيل بشريط تقدم ← تحويل ← رفع بشريط تقدم) ثم يستلم الفيديو **بغلافه (Thumbnail)** — كل ذلك عبر **تعديل نفس الرسالة** دون رسائل جديدة.

## لماذا هذه المعمارية؟
| المشكلة | الحل |
|---|---|
| GitHub يقتل الـ job بعد 6 ساعات كحد أقصى | دورات 5 ساعات تُعيد تشغيل نفسها ذاتياً + حالة Redis تُحفظ (`dump.rdb`) وتُستعاد |
| Runner واحد بطيء (تحميل تسلسلي) | **5 Runners متوازية**: بوت رئيسي منسق + 4 عمال تحميل/رفع (حتى 4 فيديوهات معاً) |
| سيرفرات التحميل تقيّد الاتصال الواحد | تحميل متوازي x16 بـ N_m3u8DL-RE (أسرع 6–7x من ffmpeg، مثبت بالقياس) |
| تليجرام الرسمي يحد الرفع بـ 50MB | سيرفر Bot API محلي ذاتي (tdlib) يرفع حتى **2000MB** لكل ملف |
| تكرار نفس الطلب يستهلك bandwidth | كاش Redis: `رابط+جودة → file_id` — الإرسال الثاني **فوري ⚡ بلا أي تحميل** (forward) |
| إشعارات/رسائل متناثرة | كل مراحل المهمة **تعديل** لرسالة واحدة + شريطا تقدم حقيقيان (■ = 10%) |
| انقطاع الدورة يضيع المهام | المهام العالقة تعود للطابور تلقائياً + مسار `/fail` يعيد المحاولة ويبلغ المستخدم |

## المزايا
- `/start` `/language` (عربي/English)، أزرار مضمنة 2×2، زر Back.
- حد 4 عمليات متزامنة، ومن زاد يُرفض برسالة انتظار.
- تقسيم تلقائي للملفات >1.9GB إلى أجزاء MP4 صالحة (PART 1/2) وإعادة تجميع موثقة.
- لا تخزين دائم: الفيديو يُحذف من الـ Runner بعد الرفع.
- صفر مكتبات بايثون خارجية (stdlib فقط) — تثبيت الأدوات من الكاش في ثوانٍ.
